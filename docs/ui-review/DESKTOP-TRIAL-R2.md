## A. 中断恢复：复现、根因与最小修复

### 旧包实际证据

在旧 DMG 安装副本创建独立验收会话，使用已有获准的 gpt-5.5，请求逐行输出 1–300；看到部分流式正文后主动停止。停止截图可见至第 267 行。切换会话返回后正文消失，显示原始 `<turn_aborted>` 文本；正常退出重启后同样缺失。旧包重载操作未单独取得完整结果，不把它列为独立通过的复现证据。

仅检查该验收会话的会话文件：存在用户请求、推理项和 `turn_aborted`，没有 assistant 正文项。已有辅助历史也不保存 agent delta。因此主要根因是**未完成 assistant 的流式正文只留在内存，没有进入正常会话持久化**，不是旧正文已写盘后被 CSS 隐藏。回放另有两个问题：原始中断控制文本被当作用户正文显示，停止状态没有明确恢复；实时完成分支也没有区分 interrupted 与普通完成。

### 本轮实现

- 新增桌面 `InterruptedTurnStore`，累积当前 turn 的未完成 assistant delta。在确认 interrupted 时，先用临时文件加 rename 保存，再转发停止事件。已正常完成的消息仍由原会话保存机制负责。
- 在现有 userData 内增加 `interrupted-turns/<thread>/<turn>.json`，schema version 1，仅保存中断状态、时间和未完成正文。没有改写或迁移原会话文件；旧数据无需转换，因此没有清空、重建或复制用户历史。原数据保留即兼容基线；旧包忽略新增文件。
- 历史事件读取合并这个附加记录，并纳入缓存签名。回放去重，保留“已中断”；原始中断控制块转成真实状态提示，未隐藏错误或权限状态。正常完成正文继续走原保存与回放。
- 已确认停止的 turn 拒绝迟到的 assistant delta、assistant item 完成及重复 turn 完成覆盖；不自动续跑、不重新请求模型。
- 修改范围涉及桌面主进程事件观察/历史读取，以及共享 renderer 历史解析和状态行展示；没有修改网页布局、模型 Router/Provider、凭据、IPC 授权或运行协议。

主要代码：`src/main/services/InterruptedTurnStore.ts`、`historyStore.ts`、`main.ts`，renderer 的 `replayParsers.ts`、`installEventPipeline.ts`、`useChatRenderModel.ts` 和中英文中断文案（路径均相对 packages/app）。

不声称修复前已经丢失且从未落盘的内容可以恢复；未验证崩溃、断电、磁盘满或存储权限故障恢复。
